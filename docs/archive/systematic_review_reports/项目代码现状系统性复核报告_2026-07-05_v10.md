## 2. 总体结论

当前项目已经具备较完整的工程骨架和大量实代码: 数据加载/预处理、Dataset、模型架构、训练、评估、API、DAVF、GenKI/PTM 虚拟扰动、外部工具客户端和可观测性均有实现与测试。与 v9 相比，若干高风险结论需要更新:

- `/initialize` API key 比较已从普通字符串比较改为 `hmac.compare_digest()`，并有缺失 key、错误 key、正确 key、dev/prod 模式与 compare_digest 调用断言测试覆盖。[src/api/routes/initialize.py:8](../src/api/routes/initialize.py#L8), [src/api/routes/initialize.py:112](../src/api/routes/initialize.py#L112), [src/api/routes/initialize.py:145](../src/api/routes/initialize.py#L145), [tests/unit/test_initialize_auth.py:52](../tests/unit/test_initialize_auth.py#L52), [tests/unit/test_initialize_auth.py:92](../tests/unit/test_initialize_auth.py#L92)
- DAVF E2E 微调脚本不再是完全空骨架: 当前会读取 `--data_path` CSV、解析序列/标签列、构建 DataLoader、计算 loss、反传、更新优化器并保存训练 metadata。[scripts/finetune_davf_e2e.py:105](../scripts/finetune_davf_e2e.py#L105), [scripts/finetune_davf_e2e.py:135](../scripts/finetune_davf_e2e.py#L135), [scripts/finetune_davf_e2e.py:184](../scripts/finetune_davf_e2e.py#L184), [scripts/finetune_davf_e2e.py:197](../scripts/finetune_davf_e2e.py#L197), [scripts/finetune_davf_e2e.py:208](../scripts/finetune_davf_e2e.py#L208)

剩余核心问题集中在四类:

1. 若干功能已可跑 smoke，但距离生产级语义和契约仍有差距，尤其是 ESM-3 真资产语义、分布式训练闭环、DAVF E2E 数据契约、Geneformer/AlphaFold fallback provenance。
2. `mypy src` 仍有 207 个错误，说明类型契约、mixin 设计和批数据结构还未达 CI 门禁水平。
3. 全量测试无法在 240 秒内完成，测试套件需要分层、标记和更短 smoke gate。
4. 多版本历史报告、静态文档生成脚本和保留的取消功能 shim 容易继续制造“需求已取消但代码像入口”的歧义。

## 5. 高优先级解决策略

### 5.1 恢复 mypy 基线

目标: `mypy src` 从 207 errors 降到 0，且不重新引入 `mypy: ignore-errors`。

执行顺序:

1. 安装 dev 类型依赖: `pip install -r requirements-dev.txt`，确认 `requests` 和 `yaml` stub 错误消失。
2. DataLoader 阶段: 将 `_DataLoaderProtocol` 真正接入 mixin 类型，优先消除 `ptm_database_loaders.py`、`file_loaders.py`、`uniprot_loader.py` 的 attr-defined。
3. Dataset 阶段: 统一 `_DatasetConfig`、`PTMDatasetBase`、`FeatureExtractor` 的 config 类型，避免 `dict[str, str | int | float | list | dict]` 造成 `.get()` union 爆炸。
4. API/GenKI/DAVF 阶段: 修复 `PredictionResponse` 构造参数、`_ReferenceData` vs `dict`、Path/string 变量复用、返回 Tensor/ndarray 不一致。

### 5.2 将 DAVF E2E 微调纳入正式训练契约

目标: 脚本训练出的 artifact 能被项目推理/评估链路识别。

执行顺序:

1. 提取 `SequenceDataset` 和 `DownstreamHead` 到可测试模块，或改用已有 PTM Dataset/DataModule。
2. 输入 CSV 支持 `sequence/ptm_sites/gene_symbol/label`，复用 PTM 解析和 DAVF mapper。
3. 保存 `config.yaml`、`manifest.json`、label mapping、dataset hash、训练步数、loss history。
4. 新增 CLI smoke: 临时 CSV + mock/lightweight DAVF checkpoint，跑 `--epochs 1`，断言 checkpoint 和 manifest 字段。

### 5.3 统一 fallback provenance 与 production strict

目标: 任何随机/合成/替代模型能力都不能伪装成真实模型能力。

执行顺序:

1. 定义统一 provenance 枚举: `real`, `fallback_random`, `synthetic_fallback`, `substituted_model`, `mock`.
2. Geneformer、AlphaFold、ESM3 wrapper、demo model、external tools 均返回 provenance。
3. API `/model/info`、预测响应和 artifact manifest 输出 provenance。
4. production 环境默认启用 `PTM2CELLNET_STRICT_MODEL_ASSETS=1` 和 `PTM2CELLNET_SAFE_LOAD_ONLY=1`。

### 5.4 测试分层

目标: 本地 1-2 分钟内能证明核心回归，完整矩阵交给 CI 分 job。

建议命令:
