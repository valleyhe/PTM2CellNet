# PTM2CellNet 项目进度与代码现状复核报告

> **生成日期**：2026-07-02
> **复核方法**：Open Dynamic Workflows（ODW）编排 + 多 Agent 并行静态代码分析 + 需求文档交叉比对 + 客观指标采集
> **覆盖范围**：`src/`（93 个 Python 文件）、`tests/`（98 个 Python 文件）、`scripts/`（23 个脚本）、`configs/`（28 个配置文件）、`docs/plans/`、`notebooks/`
> **复核基准**：`AGENTS.md` 架构设计、`docs/plans/2026-05-03-davf-integration-plan.md`、既有 `深度代码现状复核报告_v3.md`

---

## 执行摘要

本次复核采用 ODW 编排，因 ODW 底层 adapter 异常导致工作流中断，随后使用同等工作量的多 Agent 并行审计完成全部模块复核。结论如下：

- **整体健康度**：中-高。核心训练、推理、API、评估流程均可运行，单元测试总体通过。
- **关键风险**：DAVF 级联融合“架构通、数据不通”；`AGENTS.md` 与实际代码严重脱节；23 个脚本中 20 个未在交付物清单中记录；10 个源文件禁用 mypy；多处重复常量/编码器定义。
- **已修复亮点**：自 v3 报告以来，`load_from_uniprot`、`external_tools.py` 的 AlphaFold/BLAST/ClustalW/PSIPRED 四个工具已从纯存桩改为带 fallback 的实现。

## 2. 未完全实现的功能

> 功能已存在，但完成度不足或与需求规范存在偏差。

### 2.1 `PTMDataModule` 命名冲突（完成度约 60%）

- **现状**：`src/data/datasets.py:450` 中 `PTMDataModule = PTMPlainDataModule`（普通类）；`src/data/lightning_datamodule.py:20` 存在合法的 `PTMLightningDataModule(L.LightningDataModule)`；`src/data/__init__.py:6` 导出的是普通类别名。
- **缺失**：`PTMDataModule` 名称未指向 Lightning 版本；`PTMLightningDataModule` 未作为默认导出。
- **影响**：`from src.data import PTMDataModule` 得到普通类，期望 Lightning 行为时静默失败。
- **引用**：`src/data/datasets.py:450`、`src/data/__init__.py:6`

### 2.2 `load_from_uniprot`（完成度约 80%）

- **现状**：`src/data/loaders.py:541-613` 已实现批量/单个 UniProt 获取、本地 JSON 缓存、序列清洗。
- **缺失**：批量查询未限制 ID 数量，URL 过长可能导致 414 错误；未返回 `protein_name`、`organism` 等质控字段；缓存目录与 `paths` 配置耦合。
- **引用**：`src/data/loaders.py:541-613`
- **状态更新**：v3 报告称其未实现，当前已修复。

### 2.3 `DAVFInferenceModule`（完成度约 75%）

- **已实现**：加载 LatentDAVF、零特征降级、冻结、DeltaProjection、device 管理。
- **缺失**：仅支持 `scvi_latent`；不支持 `DeltaPredictor` 检查点；`z_0` 参数声明但未被消费；batch key 与 plan 不一致（plan 为 `ptm_gene_names`/`ptm_type_names`，代码为 `davf_sites`/`davf_gene_names`）。
- **引用**：`src/models/davf_inference.py:70-72`、`src/models/architectures.py:661-667`

### 2.4 `PTM2CellNet` DAVF 分支（完成度约 85%）

- **已实现**：`use_davf` 开关、配置合并、predictor 输入维度扩展、零特征降级。
- **缺失**：batch key 与 plan 不一致；`PTMDirectionMapper` 在 `__init__` 中无参构造，会立即初始化 Geneformer loader 和 `GeneMapper`，可能拖慢模型构建；未消费 `configs/davf_integration.yaml` 中的 `ptm_mapper.max_targets`、`integration.*` 字段。
- **引用**：`src/models/architectures.py:589`、`src/models/ptm_direction_mapper.py:193-215`

### 2.5 `MambaEncoder`（完成度约 60%）

- **已实现**：MambaBlock、SelectiveSSM、嵌入层、mask 处理。
- **缺失**：`_ssm_step` 使用纯 Python `for t in range(seq_len)` 串行递推，无 CUDA 并行/scan 优化。
- **引用**：`src/models/mamba_encoder.py:164-174`

### 2.6 `SignalingNetworkMapper` 集成（完成度约 30%-70%）

- **已实现**：8 条内置通路、KEGG/Reactome 集成、下游基因预测（`src/models/signaling_network.py:507`）。
- **缺失**：未集成到核心训练/预测流程；API 中虽已调用但 `effect="gain"`、`delta_prob=1.0` 为硬编码，未使用真实 PTM 效应。
- **引用**：`src/api/routes/predictions.py:184-213`、`scripts/predict_variant_effect.py`

### 2.7 `batch_predict` 张量级批处理（完成度约 80%）

- **现状**：`src/api/routes/predictions.py:260-264` 已使用 `torch.stack` 进行张量堆叠。
- **缺失**：`predict` 与 `batch_predict` 仍各自处理 pathway/计时逻辑，重复代码未彻底消除。
- **引用**：`src/api/routes/predictions.py`

### 2.8 `ModelCheckpoint`（完成度约 75%）

- **已实现**：`monitor`、`mode`、`save_best_only`、`save_last`、`verbose`。
- **缺失**：不保存完整 checkpoint（优化器/scheduler/epoch）；`save_last` 文件名生成脆弱（`.replace(".pt", "_last.pt")`）；不支持 `save_top_k > 1`。
- **引用**：`src/training/callbacks.py:53-136`

## 6. 优先级修复建议

### 6.1 短期（1 周）

1. **打通 DAVF 数据流**：在 `PTMDataset.__getitem__` 中支持基因名/通路上下文输出，或新增 collator 将 `ptm_sites` 映射为 `davf_sites`/`davf_gene_names`；同步修复 `scripts/train.py`、`scripts/predict.py`、`scripts/finetune_davf.py`。
2. **修复 `PTMDataModule` 命名冲突**：将 `PTMDataModule` 别名指向 `PTMLightningDataModule`，或拆分导出并更新所有调用方。
3. **统一 padding/编码约定**：0 padding 与 `-` padding 只能二选一，消除 `AA_TO_IDX` 重复定义。
4. **修复 API 安全**：为 `/initialize` 添加路径 `resolve()` 校验；限制请求体大小；收紧 CORS 默认来源。

### 6.2 中期（1 月）

1. **消除 mypy ignore**：逐个文件移除 `# mypy: ignore-errors`，修复类型错误。
2. **减少重复代码**：抽取编码器公共实现到 `src/models/encoders.py`；将 `PTM2CellNet` 与 `PTM2CellNetLarge` 公共逻辑抽取到基类/工厂。
3. **补齐核心未测路径**：为 `cross_validate`、排序指标、置信区间、`TwoStageExplanationPipeline`、`signaling_network.py` 核心逻辑编写单元测试。
4. **文档同步**：重写 `AGENTS.md` 以反映 24 个模型文件、16 个数据文件、10 个训练文件；更新 `模块六交付物清单.md`。
5. **序列化安全**：为 `DatasetCache` 增加版本/校验和机制；评估 `safe_torch_load` 的 `weights_only=False` 回退范围。

### 6.3 长期（1 季度）

1. **性能优化**：Mamba SSM 接入 `mamba-ssm` 或实现并行 scan；向量化 `clean_sequences`、`extract_kmer_features`；优化同源 splitter 内存占用。
2. **架构统一**：统一原生 `Trainer` 与 Lightning 训练循环；将 `PTMDirectionMapper` 输入构造能力下沉到数据模块。
3. **生产级能力**：实现 AMP、梯度裁剪、分布式训练、请求速率限制、Prometheus 监控。
4. **外部工具落地**：在脚本中实际调用 `external_tools.py` 中的 AlphaFold/BLAST/ClustalW/PSIPRED，或明确标记为实验性功能。
