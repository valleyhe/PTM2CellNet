## 1. 项目概述

PTM2CellNet 是一个"蛋白质翻译后修饰（PTM）感知"的深度学习框架：整合蛋白
序列与 PTM 位点信息，预测细胞状态（分类/回归），并提供 DAVF 方向感知扰动
模拟、变体效应预测、多任务 PTM 预测与生产级 FastAPI 服务。

- 代码规模：`src/` 123 个 Python 文件，`tests/` 136 个文件（v19 口径，本次实测一致）
- 测试基线：**1531 单元测试通过 / 5 跳过**（本轮实测 2026-08-04，与 v19 基线一致）
- 模型家族：PTM2CellNet-Base / Large / Ensemble，编码器覆盖 CNN、Transformer、
  LSTM、GRU、Mamba、ESM-2、ESM-3、ProtBERT、ProtT5
- 文档体系：`docs/PTM2CellNet_项目文档.md`（v2.0）、`docs/PTM2CellNet_技术文档.md`、
  `docs/PTM2CellNet_文件说明.md`、`docs/archive/systematic_review_reports/项目代码现状系统性复核报告_2026-07-06_v19.md`

**文档引用**：AGENTS.md「0. 实际代码现状映射」；v19 报告 §3/§5/§6；
`docs/CURRENT_STATUS.md`。

## 4. 问题分析（按严重程度排序）

### 4.1 高严重度（P1）——1 项（本轮新发现）

**P1-1 API 自动初始化默认配置与模型架构校验不兼容**

- 现象：仅设置 `PTM2CELLNET_CHECKPOINT=outputs/smoke/models/best_model.pt` 启动
  API 时，自动初始化失败：
  `Auto-initialization failed: 配置验证失败: ['缺少必需字段: model.encoder_type']`
  （实测复现，2026-08-04）。
- 根因：
  - `src/api/autoinit.py:202` 默认配置路径为 `os.environ.get("PTM2CELLNET_CONFIG", "configs/production.yaml")`；
  - `configs/production.yaml` 的 `model:` 段仅含部署字段
    `path/device/batch_size/max_sequence_length`，**无架构字段**；
  - `src/models/architectures.py:577` → `src/models/model_utils.py:80`
    `validate_model_config` 强制要求 `model.encoder_type`，导致校验必然失败。
  - 对比：`src/utils/checkpoint_utils.py:202` `resolve_inference_config` 采用
    "checkpoint 同目录 sibling config 优先"策略，autoinit 未复用该策略。
- 影响：用户按文档只设置 checkpoint 路径时，API 无法自动加载模型；必须额外
  设置 `PTM2CELLNET_CONFIG` 指向训练产物 config（实测设
  `PTM2CELLNET_CONFIG=outputs/smoke/models/best_model.config.yaml` 后
  `/health` 200 + `/predict` 200 正常）。
- 修复路径见 §5.1。

### 4.2 中严重度（P2）——2 项

**P2-1 数据管线不产出推荐 provenance 列，泄漏审计能力受限**

- 现象：`scripts/train.py` 运行输出警告：
  `数据契约: 缺少推荐 provenance 列: protein_accession, gene_symbol, source_db, evidence_level, split_group（影响 dataset_hash/leakage 审计与发布门禁）`（实测复现）。
- 根因：`src/data/data_contract.py:14-20` 将上述列定义为 Recommended；
  但 `scripts/prepare_data.py`、`scripts/integrate_data_v2.py`、
  `src/data/preprocess.py` 均无产出这些列的逻辑（grep 全仓 0 命中）。
- 影响：dataset_hash/同源泄漏审计无法基于真实基因标识执行；发布门禁
  （`artifacts.py` manifest `deployable` 字段）对真实数据无法做出强断言。

**P2-2 smoke 训练产物中的模型卡片引用解析**（观察项）

- `outputs/smoke/models/best_model.config.yaml` 中 `model.encoder_type` 存在
  但被 `configs/production.yaml` 覆盖验证失败（同 P1-1 根因链，合并处理）。

### 4.3 低严重度（P3）——9 项（含本轮 3 项新观察）

## 5. 解决方案与实施计划

### 5.1 P1-1 API 自动初始化默认配置缺陷

| 项 | 内容 |
|----|------|
| 目标 | 设置 `PTM2CELLNET_CHECKPOINT` 后 API 可自动加载模型，无需额外指定 config |
| 步骤 | ① `src/api/autoinit.py` `_try_auto_initialize` 中改用 checkpoint sibling config（复用 `resolve_inference_config` 语义）；② sibling 缺失时回退 `PTM2CELLNET_CONFIG`，仍缺失则明确报错而非带错误配置继续；③ 新增测试：仅设 checkpoint 启动 → `/health` healthy |
| 时间节点 | 2026-08-11 前（1 个工作日；含测试与回归） |
| 验证 | `PTM2CELLNET_CHECKPOINT=outputs/smoke/models/best_model.pt pytest tests/unit/test_api_auto_initialize.py` |

### 5.2 P2-1 数据管线 provenance 列

| 项 | 内容 |

## 6. 结论与建议

### 结论

1. **E2E 训练与推理能力基本达标**：本轮实测完成 数据→训练→评估→artifact→CLI 推理→API 推理 全链路闭环；1531 单元测试通过，与 v19 基线一致。
2. **无 P0 阻塞项**；v19 后本轮新发现 1 项 P1（API 自动初始化默认配置缺陷，§4.1），
   根因明确、修复范围小（autoinit 配置解析一处）。
3. 代码与文档一致性已恢复：历史报告/设计文档全部归档至 `docs/archive/`（6 个分类目录），
   `CURRENT_STATUS.md` 与归档 README 引用已修复指向 v19 归档位置。

### 建议

1. **优先修复 P1-1**（1 个工作日）：影响 API 部署开箱即用体验，是当前唯一
   "文档所述用法与实际行为不一致"的点。
2. **落实 P2-1 provenance 列**：真实数据训练前补齐，否则发布门禁与泄漏审计
   形同虚设。
3. **维持归档纪律**：新报告/复核轮次产出后即时归档旧版，避免 docs 根目录
   再次累积历史快照（本次归档后 docs 根仅保留 4 份活跃文档 + api/guides 体系）。
4. **环境类验收项（F-03/04/05）**在资源就绪时按 §5.4 闭环，并将结果回填
   下轮系统性复核报告。
