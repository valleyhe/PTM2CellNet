# PTM2CellNet E2E 训练与推理现状分析

- 审计日期：2026-08-08
- 审计范围：当前工作树中标准 PTM2CellNet 链路、跨尺度离线链路、数据清单、模型资产、训练恢复、推理 artifact、API、测试与发布门禁。
- 证据原则：以下结论只使用本仓库代码、配置、测试、数据资产检查和本次实际执行命令；合成 smoke 通过不等价于真实生物数据验收通过。

## 1. 项目概述

PTM2CellNet 当前存在两条相互独立的运行链路：

1. 标准链路：以 <code>src/models/architectures.py</code> 的 PTM2CellNet 为核心，由 <code>scripts/train.py</code>、<code>scripts/predict.py</code> 和 FastAPI 路由组成。该链路已有训练、验证、checkpoint、最佳权重导出、单样本/批量推理和 API 测试。
2. 跨尺度链路：以 <code>src/models/cross_scale.py</code> 为模型核心，由 <code>src/data/cross_scale_dataset.py</code>、<code>src/training/cross_scale_trainer.py</code>、<code>scripts/train_cross_scale.py</code> 和 <code>scripts/predict_cross_scale.py</code> 组成。该链路目前是离线 CLI 与 NPZ artifact 链路，不属于标准 API 服务链路。

本轮变更已经把跨尺度训练/推理的可执行骨架、输入 schema、checkpoint schema、pLM 资产检查和数据 manifest profile 接入仓库，并修复了标准训练的两个关键契约问题：

- 标准训练 resume 从已完成 epoch 的下一轮开始，避免重复训练已完成 epoch。
- <code>best_model.pt</code> 从 <code>checkpoint_best.pt</code> 导出，而不是直接导出最后一轮内存权重。

当前结论：

- 标准训练、标准推理和标准 API：具备工程级 smoke/回归验证基础。
- 跨尺度合成数据训练/推理：具备工程级 smoke 骨架和 artifact 契约。
- 跨尺度真实数据训练、真实科学验收以及跨尺度 API：尚未达到可宣称的 E2E 完成状态。
- 当前仓库整体测试通过，但真实资产测试仍按设计 skip，且部分 profile 因缺少授权真实快照而 fail-fast；这属于发布边界而不是测试框架故障。

当前不能宣称以下结论：

5. 旧版纯权重 checkpoint 的 resume 与完整状态 checkpoint 等价。

## 4. 问题分析

### 4.1 阻断项（P0）

#### P0-01：跨尺度真实输入资产不完整

<code>cross_scale_training</code> profile 当前缺少 8 个 required 数据项；PMADS 本地文件存在且哈希通过，但真实 gene embedding、graph、perturbation/target 等输入未形成完整可审计快照。<code>CrossScaleNPZDataset</code> 设计为消费预计算 NPZ，不会自动把原始序列、pLM 服务和图数据拼成训练输入。

影响：无法运行真实跨尺度训练，也无法证明真实数据分布、维度和标签契约正确。

#### P0-02：跨尺度链路未接入标准 API

API 初始化路由和自动初始化路径构建标准 PTM2CellNet；没有跨尺度模型类型、artifact 适配器、NPZ/序列输入转换和专用资源限制。

影响：若 E2E 目标包含 API 推理，跨尺度能力在服务层完全缺失。

#### P0-03：真实科学验收缺少可复现基线

真实资产测试全部按缺失资产或显式开关 skip，当前通过的跨尺度测试使用合成数据。缺少固定数据快照、预期标签版本、真实指标阈值、外部工具版本和验收命令。

影响：工程测试绿色不能转化为科学结论或发布资格。

### 4.2 高优先级问题（P1）

#### P1-01：callback 状态没有进入 checkpoint

<code>ModelCheckpoint</code> 保存模型和训练状态，但没有保存自身的 best_value/top-k tracking；<code>EarlyStopping.on_train_start</code> 会重置 wait、best_value 和 should_stop。跨进程 resume 后，训练权重可恢复，但 best/early-stop 历史不完全连续。

建议：为 callbacks 增加 state_dict/load_state_dict，并将 callback_states 写入 checkpoint；恢复后再调用训练开始钩子时不得覆盖已恢复状态。

#### P1-02：原始序列到三路 embedding 的生产前处理缺失

跨尺度当前入口是带有预计算 embedding 的 NPZ。生产需要明确的序列清洗、pLM batch 推理、最大长度策略、GPU/CPU fallback、分片、缓存键、失败重试、数据划分隔离和 embedding provenance。

影响：训练脚本可以运行，但无法由原始研究输入稳定重建同一训练样本。

#### P1-03：关键模块的测试深度不均衡

全局 branch coverage 75.63% 达到当前门禁，但仍有低覆盖模块：<code>src/training/self_supervised.py</code> 31.62%、<code>src/api/routes/initialize.py</code> 47.88%、<code>src/data/validation.py</code> 53.65%、<code>src/inference/cross_scale_predictor.py</code> 51.45%、<code>src/models/plm_assets.py</code> 66.42%。这些模块分别涉及恢复、初始化、缓存/安全加载、artifact 消费和模型资产检查。

影响：全局数字掩盖了少数关键路径的异常分支和环境失败分支。

#### P1-04：跨尺度数据 profile 与代码入口没有形成真实验收闭环

manifest 已能 fail-fast，但缺失项没有对应的数据生成脚本、快照登记、哈希更新流程和数据负责人交付定义。

影响：问题能被检测，却不能由仓库内流程自动闭环解决。

### 4.3 中优先级问题（P2）

- API 限流是进程内状态；Docker/多 worker 生产部署需要 Redis、网关或其他共享限流方案。
- <code>requirements-lock.txt</code> 含指向 <code>/tmp</code> 的本地依赖 URI，Dockerfile 仍使用宽泛的 Python 基础镜像，环境可移植性不足。
- 本地 pLM 目录中存在 .part/.tmp 文件；资产检查已拒绝把它们当作完整权重，但清理/下载恢复策略仍需文档化。
- 现有代码和文档保留了已取消的实时质谱流、自定义 PTM 数据库和 GUI 兼容入口；这些内容不应重新进入 roadmap 或新增实现。
- 测试仍有 28 个 warning，主要包括 Pydantic/Starlette 兼容提示、Lightning dataloader worker 提示、Mamba AMP API 弃用和已取消功能的 deprecated test；应按依赖升级窗口处理。

## 5. 解决方案与实施计划

### 阶段 A：真实数据与资产闭环（2026-08-10 至 2026-08-14）

目标：让 cross_scale_training 和 cross_scale_inference profile 在明确授权的真实快照上通过。

实施：

1. 补齐 8 个 required dataset 项，逐项登记来源、版本、路径、大小、SHA-256、许可证和负责人。
2. 固定 gene universe、标签字典、graph 节点顺序、edge index/map 和 perturbation target schema。
3. 完成三路 pLM 资产下载/校验，删除或隔离 .part/.tmp，记录 tokenizer/config/权重文件摘要。
4. 运行两个 manifest profile 和 validate_plm_assets，将输出保存为验收附件。

完成标准：两个真实 profile 文件与哈希全通过；输入快照可在干净工作区重建；缺失输入仍能 fail-fast 且错误可定位。

### 阶段 B：embedding 与数据预计算（2026-08-17 至 2026-08-21）

目标：从原始序列稳定生成跨尺度 NPZ，而不是手工准备输入。

实施：

1. 增加离线预计算入口，支持 batch、最大长度、设备选择、断点续跑和失败样本清单。
2. 缓存键绑定序列 hash、pLM model revision、tokenizer/config 摘要和预处理版本。
3. 明确 train/validation/test 的数据划分先后顺序，禁止跨 split 共享会产生泄漏的拟合状态。
4. 对 embedding shape、NaN/Inf、gene 顺序、graph 节点映射和 targets 做生成后校验。
5. 生成 NPZ、manifest 和 provenance JSON，并新增 raw sequence 到 NPZ 的集成回归测试。

完成标准：从固定原始快照得到的 NPZ 可重复；中断后可继续；任一维度/顺序不一致会在训练前失败。

### 阶段 C：服务适配与 API 契约（2026-08-24 至 2026-08-28）

目标：明确是否把跨尺度推理纳入 API；若纳入，完成可控的专用服务路径。

实施：

1. 定义 model_type=standard/cross_scale 的配置和 artifact manifest 兼容层。
2. 为跨尺度预测器定义请求 schema、输入大小上限、batch 上限、超时、设备和资源隔离。
3. 明确在线输入是预计算 NPZ、gene/embedding 引用，还是原始序列；不允许隐式下载或隐式生成昂贵 embedding。
4. 接入 initialize、model info、health/ready、predict、batch_predict 和 metrics。
5. 增加 API 错误码、权限、限流和并发测试；多 worker 采用共享限流策略。

完成标准：API 能加载指定跨尺度 artifact，拒绝错误 schema/维度，输出 provenance，并有稳定的集成测试和部署说明。若产品不需要该能力，则应把“离线 CLI only”正式写入范围并关闭 P0-02。

### 阶段 D：真实科学验收（2026-08-31 至 2026-09-04）

目标：把工程可运行性与科学有效性分开验收。

实施：

1. 固定标签版本、数据切分和随机种子。
2. 定义分类/回归/排序指标、置信区间、校准和基线比较阈值。
3. 运行真实 train/validation/test、同源外推和必要的外部工具对照。
4. 记录显存、耗时、吞吐、失败样本和模型/数据 provenance。
5. 生成不可变验收报告，标明通过、条件通过或阻断项。

完成标准：真实数据测试不再仅依赖 skip；每个指标有阈值、样本量和可复现实验命令。

### 阶段 E：恢复、覆盖率与运行维护（2026-09-07 至 2026-09-11）

目标：收敛剩余发布风险。

实施：

1. 给 ModelCheckpoint、EarlyStopping、scheduler monitor 等 callback 增加状态序列化和恢复测试。
2. 为 self-supervised、API initialize、validation、cross-scale predictor 和 pLM asset checker 补齐异常/恢复/环境分支。
3. 固定依赖构建来源，移除不可移植的本地 file URI，锁定 Docker 基础镜像和关键 CUDA/PyTorch 组合。
4. 处理或登记 28 个 warning，明确哪些由上游依赖升级解决。
5. 更新 CURRENT_STATUS、TEST_COVERAGE、real-assets acceptance 和发布清单。

完成标准：callback resume 回归通过；关键模块覆盖率达到项目设定阈值；从干净环境构建并完成最小训练/推理/API smoke。

## 6. 结论与建议

当前代码已经从“跨尺度只有设计意图”推进到“跨尺度离线合成 smoke 可执行”，并且标准训练链路的 resume 与 best artifact 两个高风险契约已修复。全仓库最终测试为 1897 passed、13 skipped、28 warnings，说明当前代码变更没有引入已观测的回归。

但这不等价于完整 E2E 交付。真正的发布阻断点是跨尺度真实输入资产、原始序列到 embedding 的可重建生产前处理、科学验收，以及（若产品要求）跨尺度 API 接入。建议按 P0→P1→P2 顺序推进；在 P0-01 和 P0-03 关闭前，不应把跨尺度结果标记为真实数据生产结果。

若产品范围明确只支持离线跨尺度 CLI，则应记录该决策，关闭 API 适配项，改为要求 CLI artifact、数据 manifest 和 provenance 的离线发布验收；否则应按阶段 C 实现专用服务链路。
