# PTM2CellNet E2E 训练与推理现状分析

- **报告日期**：2026-08-08
- **评估对象**：本地工作区的标准 `PTM2CellNet`、opt-in `CrossScalePTM2CellNet`、数据清单、PMADS Ridge 基线、CLI、FastAPI、测试与发布门禁
- **评估口径**：代码与可执行测试优先；历史设计只用于需求追溯。工程 fixture、随机初始化权重和 mock 不作为真实生物学效果证据。

## 1. 项目概述

PTM2CellNet 当前有两条能力线：

1. **标准生产候选链路**：蛋白序列与 PTM 位点经过预处理、编码、融合和分类/回归头，支持训练 CLI、评估、checkpoint、批量预测 CLI 和 FastAPI。
2. **跨尺度研究链路**：`MultiPLMEncoder`、`PTMTokenAdapter`、`CIGNNSignalBridge`、`CellGraphCompassHead` 和 `CrossScalePTM2CellNet` 已组成可微的蛋白/PTM→信号图→细胞状态工程契约，但目前只接入合成 fixture 测试与 CPU smoke benchmark。

仓库当前包含 128 个 `src/` Python 文件、140 个测试文件、30 个 Python 脚本和 30 个 YAML 配置。数据清单登记 15 个数据源；本地 PMADS/CPTAC 两个快照已登记 SHA-256，其余单细胞扰动和信号图数据仍处于 `controlled` 且没有本地快照路径。[数据清单](../data/manifests/datasets.yaml#L252) [数据更新流程](DATA_UPDATE_WORKFLOW.md)

### 1.1 本次结论摘要

- **标准模型工程 E2E：可运行。** 数据质量 fail-fast、标签映射、训练、checkpoint、独立评估、artifact manifest、CLI 推理与 API 推理均有实现和自动化测试；API router 统一挂载在 `/api/v1`。[训练入口](../scripts/train.py#L107) [预测入口](../scripts/predict.py#L382)
- **跨尺度工程组件：可运行。** 模型支持 forward、联合 loss、反向传播、配置与 state-dict round-trip、provenance；但证据来自内存 embedding/图 fixture。[跨尺度模型](../src/models/cross_scale.py#L1206) [集成测试](../tests/integration/test_cross_scale_pipeline.py#L31)
- **跨尺度科学 E2E：未闭环。** 没有跨尺度 DataModule/训练入口、真实 pLM/图/扰动 target 验收、专用 checkpoint artifact 或推理/API 接入。
- **覆盖率不足问题已建立可持续门禁，但尚未达到高保障水平。** 当前核心套件 branch coverage 为 75.02%，CI 下限为 74%；低覆盖核心模块仍集中在自监督训练、初始化路由、数据验证和训练回调。[覆盖率治理](TEST_COVERAGE.md)

## 3. 当前评估结果

### 3.1 已闭环能力

1. 标准训练入口执行配置加载、数据质量报告、切分、标签映射、DataModule、模型构建、训练、测试评估和 artifact 导出；关键失败在训练前暴露。
2. 标准推理入口要求匹配的 checkpoint/config，默认拒绝缺失生产标签映射，并复用 API 预处理逻辑。
3. API 的初始化和自动初始化均明确构建标准 `PTM2CellNet`；`/api/v1` 下的预测路由支持单条、批量和变体请求。[initialize.py](../src/api/routes/initialize.py#L258) [autoinit.py](../src/api/autoinit.py#L255)
4. 跨尺度组件的维度、mask、图边、PTM token、敏感度矩阵、梯度与 provenance 已由单元/集成测试覆盖。
5. 数据 manifest CLI 能校验 15 个数据源；`--check-files --strict` 对当前登记的两个 PMADS 本地文件校验通过。
6. 覆盖率配置、开发依赖和 CI workflow 已形成可重复的 CPU 默认门禁；测试不足不再只依赖人工发现。

### 3.2 只能视为“工程就绪”的能力

- `CrossScalePTM2CellNet.forward()` 完整连接 protein/PTM、signal graph 和 cell head，并能计算联合 loss，但测试输入是随机的预计算 pLM embedding、fixture 图和随机 target。
- PMADS Ridge 是可复现参照管线；只有与复杂模型使用同一数据 release、同一 group split 后，指标才可用于科学比较。
- CPU benchmark 明确是小型 contract smoke，不提供吞吐容量规划、GPU 显存上限或真实 pLM 延迟结论。
- manifest 的 `controlled`/空路径能诚实表达资产缺失，但当前全部这类文件 `required: false`，因此严格校验通过只代表“清单合法”，不代表“科学训练资产齐备”。

### 3.3 当前不可宣称的能力

- 不可宣称三路 pLM、真实信号图和单细胞扰动数据已完成训练或效果复现。
- 不可宣称跨尺度模型已由 CLI/API 部署。
- 不可用 8 个真实资产测试的 skip 推出真实资产验收通过。
- 不可用 75% 综合覆盖率推出所有核心路径均被充分测试。

## 4. 问题分析（按严重程度）

### 4.1 阻断项（P0）

#### P0-01：跨尺度训练编排缺失

**证据**：`scripts/train.py` 固定构建 `PTM2CellNet.from_config()`；仓库内 `CrossScalePTM2CellNet` 的脚本消费者只有 fixture benchmark，没有训练 DataModule、collate、optimizer/epoch loop、best-checkpoint 或 artifact 导出。

**影响**：跨尺度模型只能做单 batch 工程验证，无法从受控 release 重复训练，也无法生成可部署 checkpoint。

**解决目标**：提供独立、opt-in、不会改变标准模型默认行为的跨尺度训练入口，并复用现有质量、日志、checkpoint 和 artifact 基础设施。

#### P0-02：真实监督与图/权重资产未形成激活后的发布门禁

**证据**：scPerturb、Norman/Adamson、Replogle、scGeneScope、kinase-substrate、STRING、BioPlex 和 RegNetwork 均为 `controlled` 且路径为空；当前只有 PMADS/CPTAC 两个本地哈希快照。[manifest](../data/manifests/datasets.yaml#L301)

**影响**：没有真实 `delta_expression`/cell-state target、signal-to-gene map、细胞图和 pLM 权重组合，不能验证学习有效性、数据泄漏、跨数据集泛化或生物学一致性。

**解决目标**：引入“研究 profile”激活清单；profile 中声明为 required 的 release 缺失、哈希漂移或 schema 不合格时必须失败。

#### P0-03：跨尺度推理与服务契约缺失

**证据**：预测 CLI、手工初始化和自动初始化均只构建标准 `PTM2CellNet`；API schema 不包含图资产 release、pLM provenance 或 `delta_expression` 输出。

**影响**：即使产生跨尺度 checkpoint，也没有受支持的加载、预处理、批处理、响应和兼容性校验路径。

**解决目标**：先完成离线 `predict_cross_scale.py`，通过真实 checkpoint round-trip 后再以显式模型类型接入 API。

### 4.2 高优先级问题（P1）

| 编号 | 问题 | 影响 | 修复方向 |
|---|---|---|---|
| P1-01 | 标准 `--resume` 不恢复 optimizer/scheduler | 恢复后 LR 重新 warmup，不能视为精确续训 | 在 checkpoint 中保存 optimizer、scheduler、scaler、RNG 与 sampler 状态，并做中断前后等价测试 |
| P1-02 | 真实资产测试默认全部 skip | 工程回归稳定，但科学回归盲区持续存在 | 配置受控 nightly runner；缺少授权资产时保持 skip，不伪造通过 |
| P1-03 | 覆盖率分布不均 | 初始化、回调、自监督和验证异常路径回归风险高 | 按模块设阶段阈值；优先异常、恢复和状态转换分支，逐轮提高全局 ratchet |
| P1-04 | manifest 没有激活 profile/必需资产集合 | `--strict` 可在关键研究资产全空时通过 | 增加 profile、release ID、required 条件和跨资产一致性检查 |
| P1-05 | 标准与跨尺度数据契约分离 | 训练/推理 shape、词表和映射可能漂移 | 定义 versioned `CrossScaleBatch` schema 和同源 collate/preprocess |
| P1-06 | 依赖只有分层 requirements，无完全锁定环境 | pLM/图/GPU 组合重建存在版本漂移 | 输出 Python/CUDA/Torch/Transformers 锁文件或容器 digest，并随 artifact 保存 |

### 4.3 中优先级问题（P2）

- Pydantic v1 compatibility、AMP/Mamba API 等弃用警告应在上游移除前完成迁移。
- 当前速率限制为进程内状态时，多 worker/多实例之间不能共享配额；生产部署需外部限流存储或网关。
- 长序列窗口逻辑和 Mamba SSM 串行实现仍有维护/性能债，需先建立可重复 benchmark 再优化。
- `estimate_max_batch_size` 的硬编码层数会在架构变化后低估/高估资源，需要从实际模型配置派生。
- 文档中的数据规模、测试计数和“最新报告”链接必须由 CI 或更新脚本检查，避免再次成为过期权威。

## 5. 解决方案与实施计划

以下日期以 2026-08-08 为基准；真实资产阶段取决于数据所有者完成许可和本地交付。

### 阶段 A：资产与目标契约（2026-08-10 ～ 2026-08-14）

**目标**：让“资产齐备”成为机器可判定条件。

1. 为 manifest 增加 `profiles.standard_training`、`profiles.cross_scale_training`、`profiles.cross_scale_inference`。
2. 固定 `delta_expression`、cell-state、gene vocabulary、signal-to-gene map、graph edge/type 和 split-group schema。
3. 为真实 pLM、图和扰动数据登记 release、license decision、SHA-256、行/节点/边数及 preprocessing version。
4. 新增 `validate_data_manifest.py --profile cross_scale_training --strict --verify-hashes`。
5. 验收：任何必需资产缺失、哈希漂移、基因词表不一致或跨 split group 重叠均 fail-fast。

### 阶段 B：跨尺度训练闭环（2026-08-17 ～ 2026-08-21）

**目标**：从受控数据 profile 训练并产出自描述 checkpoint。

1. 新增 versioned `CrossScaleDataset`/collate 与内存/磁盘流式图 batch。
2. 新增 `scripts/train_cross_scale.py`，复用 seed、日志、AMP、梯度裁剪、累积和 early stopping。
3. 扩展 checkpoint 保存 model/optimizer/scheduler/scaler/RNG/split/词表/图摘要/pLM 摘要。
4. 导出 config、metrics、predictions、data contract、artifact manifest 和 model card。
5. 验收：小型真实 release 可完成 train→val→test；中断恢复与连续训练在容差内等价；无跨组泄漏。

### 阶段 C：离线推理与 API（2026-08-24 ～ 2026-08-28）

**目标**：建立与训练同源的跨尺度推理路径。

1. 新增 `scripts/predict_cross_scale.py`，只接受自描述 artifact 与匹配的资产 profile。
2. 支持单样本/批量预测、`delta_expression`、cell-state probability 与完整 provenance。
3. 增加显式 `model_type` 路由；标准模型默认行为不变。
4. 在 API 接入前完成 schema version、响应大小、图缓存、并发和失败语义测试。
5. 验收：训练测试集导出与重新加载预测逐样本一致；错误 release/config/checkpoint 明确失败。

### 阶段 D：真实资产与科学验收（2026-08-31 ～ 2026-09-04）

**目标**：把工程可运行提升为有边界的科学证据。

1. 在同一 group split 上运行 PMADS Ridge、标准 PTM2CellNet 与跨尺度模型。
2. 报告分类/回归、校准、置信区间、分数据源/细胞类型切片和外部验证结果。
3. 做 pLM、PTM adapter、信号图、cell graph 消融；检查 shortcut/leakage。
4. 固化 GPU 峰值显存、吞吐、OOM 恢复和长序列行为。
5. 验收：预先登记阈值全部满足；未满足时记录负结果，不修改门槛追逐指标。

### 阶段 E：质量与运维收口（2026-09-07 ～ 2026-09-11）

**目标**：提高回归保障并消除发布运行时风险。

1. 将全局 branch coverage ratchet 从 74 逐步提升到 78，再根据模块增量提升到 80。
2. 先把 P1-03 四个核心低覆盖模块提高到至少 70%，覆盖正常、边界、异常和回归场景。
3. 完成 Pydantic/AMP 弃用迁移和多实例限流方案。
4. 在 nightly 运行真实资产、GPU 和外部服务分层测试；PR 默认门禁保持无网络可重复。
5. 为文档链接、测试基线和数据规模增加自动一致性检查。

## 6. 结论与建议

当前项目已经具备**标准 PTM2CellNet 的工程训练/推理闭环**，并通过 branch coverage 75.02% 的可重复核心门禁。覆盖率不足已从“不可量化”转为“有基线、有 CI、有优先模块”的治理问题；最有效的下一步是补高风险状态分支并逐步提高 ratchet，而不是追求一次性虚高总数。

跨尺度部分的正确状态是：**核心数学/接口组件与 synthetic E2E 已实现，真实训练、部署和科学验收尚未完成**。优先级应是资产 profile 和训练编排，其次才是 API 接入；在真实 target、图、pLM release 和防泄漏 split 齐备前，不应把跨尺度能力标为生产或科学就绪。

建议项目状态采用三层标签持续报告：

- `engineering-smoke-ready`：合成/fixture 能执行并通过契约测试；
- `real-asset-validated`：指定 release 在受控环境通过端到端验证；
- `scientifically-accepted`：预注册指标、基线、消融和外部验证满足标准。

当前标准模型处于第一层并具备生产候选工程链路；跨尺度模型处于第一层的组件/单 batch 范围，尚未达到第二层。
