## 四、关键风险链

以下技术债形成复合风险链，单独修复某一项不足以消除风险：

### 4.1 安全风险链

```
DEBT-15 (CORS开放) + DEBT-23 (predict无认证) + DEBT-28 (无输入长度限制) + DEBT-03 (pickle RCE)
  → 攻击者可通过CORS访问未认证端点 → 发送超长序列 → 触发不安全pickle反序列化 → 远程代码执行
```

**解决优先级**: DEBT-01 > DEBT-23 > DEBT-28 > DEBT-03 > DEBT-15

### 4.2 架构风险链

```
DEBT-04 (循环导入) + DEBT-05 (STATE竞态) + DEBT-16 (predict接口不一致) + DEBT-07 (Any泛滥)
  → 添加新schema功能可能破坏循环依赖 → STATE竞态在并发下暴露 → predict接口重构风险因Any而不可检测
```

**解决优先级**: DEBT-04 > DEBT-05 > DEBT-16 > DEBT-07

### 4.3 测试风险链

```
DEBT-11 (51模块无测试) + DEBT-12 (无API E2E) + PARTIAL-06 (scvi Any类型) + PARTIAL-05 (GenKI Any类型)
  → 安全和架构修复无法验证 → Any类型掩盖的bug在重构时暴露 → 无E2E保护回归
```

**解决优先级**: DEBT-12 > DEBT-11(安全相关模块优先) > Any类型修复

### 4.4 依赖风险链

```
DEBT-13 (12个未声明依赖) + DEBT-14 (19个包无上界) + DEBT-30 (重复声明)
  → 不可复现构建 → 破坏性主版本静默引入 → 安装冲突
```

**解决优先级**: DEBT-14 > DEBT-13 > DEBT-30
