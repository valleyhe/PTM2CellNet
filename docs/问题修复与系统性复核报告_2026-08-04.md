## 2. 每轮迭代的执行情况与结果

### 第 1 轮：P1-1 API 自动初始化默认配置缺陷

**问题识别**（复现）：
仅设置 `PTM2CELLNET_CHECKPOINT=outputs/smoke/models/best_model.pt` 启动 API →
`Auto-initialization failed: 配置验证失败: ['缺少必需字段: model.encoder_type']`。
根因链：`src/api/autoinit.py` 默认 `PTM2CELLNET_CONFIG=configs/production.yaml`
（部署配置，`model` 段仅 path/device/batch_size/max_sequence_length）→
`PTM2CellNet.from_config` 校验（`src/models/architectures.py:577` →
`src/models/model_utils.py:80`）必然失败。

**方案设计**（结合《评估报告》§5.1 方案 + 现状分析）：
配置解析优先级定为 **显式 `PTM2CELLNET_CONFIG` > checkpoint sibling config 发现 >
明确报错并拒绝加载**。与《评估报告》§5.1 的"优先 sibling"略有差异，原因是
现有测试契约（`test_api_auto_initialize.py`）要求显式 CONFIG 必须覆盖 sibling
（指向自定义 config 的场景），显式优于隐式是更安全的选择。同时废弃
"默认落到 production.yaml"的错误行为。

**代码修改**：
- `src/api/autoinit.py`：`config_path` 解析逻辑重写；import `sibling_config_path`
  （复用 `src/utils/checkpoint_utils.py:131`，与 `resolve_inference_config` 语义对齐）
- 无配置/配置不存在时输出明确错误日志并返回（不再带错误配置继续）

**单元测试**：`tests/unit/test_api_auto_initialize.py` 新增 2 个回归测试
（sibling 发现自动加载；无配置时拒绝加载 + 明确日志）。

**集成验证**：
| 命令 | 结果 |
|------|------|
| `pytest tests/unit/test_api_auto_initialize.py` | 13 passed |
| `pytest tests/unit/test_api{,_lifespan,_routes}.py test_app_factory.py` | 81 passed, 1 skipped |
| 真实场景：仅设 CHECKPOINT（smoke 产物） | `/health` 200 healthy；`/predict` 200 返回预测 |

**未解决问题**：无（本问题闭环）。

### 第 2 轮：P2-1 数据管线 provenance 列产出 + 发布门禁

**问题识别**：
`scripts/train.py` 对真实数据输出警告"缺少推荐 provenance 列
(protein_accession/gene_symbol/source_db/evidence_level/split_group)"
——《评估报告》§4.2 判定为 P2：真实数据管线（`integrate_data_v2.py`、
`prepare_data.py`）不产出这些列，dataset_hash/泄漏审计与发布门禁不可用。

**方案设计**（《评估报告》§5.2 四步方案落地）：
1. `integrate_data_v2.py` 产出四列（protein_accession=UniProt accession；
   gene_symbol 用**本地离线** `human_idmapping.gz` 映射；source_db 按数据源；
   evidence_level=database）
2. `train.py` 划分后写回 `split_group`（train/val/test）
3. `data_contract.validate_data_contract` 新增 `require_recommended` 参数
4. train.py 对真实数据（非 demo）启用该参数；**契约硬失败不中止训练**
   （工程迭代不受阻），但 manifest 显式 `deployable=False`

> 与《评估报告》§5.2 方案④"升级为 error"的差异：原代码"硬失败→标记
> deployable=False"分支因缺列只产生 warning 而**从未触发**（形同虚设）；
> 修复后该分支真实生效——缺列 → `ok=False` → `deployable=False`。选择
> "训练继续 + 不可发布"而非"中止训练"，避免破坏现有真实数据工作流
> （旧数据可继续迭代，发布被门禁拦截）。

**代码修改**：
- `scripts/integrate_data_v2.py`：新增 `_load_gene_symbol_map()`（离线 idmapping）；
  `build_dataset()`/`integrate_labels()` 产出 provenance 列
- `scripts/train.py`：split_group 写入；契约检查启用 `require_recommended`；
  `write_artifact_manifest(deployable=...)` 显式传递
- `src/data/data_contract.py`：`require_recommended` 参数 + 可操作修复指引

**单元测试**：新增 `tests/unit/test_integrate_data_v2_provenance.py`（9 个）+
`test_data_contract.py` 新增 2 个严格模式测试。

**集成验证**（真实数据实测，双向闭环）：
| 场景 | 结果 |
|------|------|
| sample_data.csv（demo） | 训练成功，缺列保持 warning，`deployable=False`（demo 语义），无回归 |
| 真实数据子集（无 provenance 列） | 训练完成，契约硬失败 warning，`model_kind=real` + `deployable=False` |
| 真实数据子集（补齐 5 列） | 训练完成，契约通过，`deployable=True` |
| `pytest tests/unit/data/ test_data_contract.py test_integrate_data_v2_provenance.py test_scripts.py` | 61 passed |

**未解决问题**：无（本问题闭环）。
