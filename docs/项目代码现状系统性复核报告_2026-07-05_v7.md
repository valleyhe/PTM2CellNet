## 2. 未实现功能清单

### 2.1 AGENTS 架构契约仍有一个模块级入口缺口

AGENTS 架构文档要求模块级 `load_and_preprocess(data_path: str) -> pd.DataFrame`、`extract_features(df: pd.DataFrame) -> np.ndarray`、`train(model, datamodule, config) -> nn.Module`。当前 `train()` 已实现为便利函数 [src/training/trainers.py:510](../src/training/trainers.py#L510)，但未发现模块级 `load_and_preprocess()`。特征提取存在 `FeatureExtractor.extract_features()` 方法 [src/data/features.py:691](../src/data/features.py#L691)，不是文档声明的模块级 `extract_features(df)`。影响较低，但这是公开接口契约与实现不一致，应该补薄封装或修正文档。

### 2.2 V2-02 实时质谱流已取消

2026-07-05 范围裁剪后，实时质谱流不再是未实现缺口或后续计划项。当前 API 继续服务 batch prediction；不再规划队列/Kafka/stream consumer、在线 PTM 解码、背压、幂等 offset、在线预测或相关监控。

### 2.3 V2-03 自定义 PTM 数据库已取消

2026-07-05 范围裁剪后，自定义 PTM 数据库不再是未实现缺口或后续计划项。公共 PTM 数据源和标准 CSV/TSV/JSON 等文件导入仍可继续使用；不再规划用户自带数据库、版本化 catalog、API 加载/查询端点、训练配置集成、冲突合并策略或 provenance 流转。

### 2.4 V2-04 分布式训练仍是最小 helper

roadmap 将 distributed training 标记为 deferred [src/models/roadmap.py:91](../src/models/roadmap.py#L91)。当前 `distributed_trainer()` 在多 GPU 时构造 Lightning `Trainer(strategy="ddp")`，Lightning 不可用则回退普通 `Trainer` [src/models/roadmap.py:235](../src/models/roadmap.py#L235)。缺失 CLI 参数矩阵、FSDP/DeepSpeed、分布式 sampler 策略、checkpoint 聚合、artifact 一致性测试和多 GPU E2E。

### 2.5 V2-05 GUI 已取消

2026-07-05 范围裁剪后，GUI 不再是未实现缺口或后续计划项。支持界面限定为 CLI、Python API 和 FastAPI；不再规划 Streamlit、Gradio、桌面 GUI、预测调用页面、artifact 选择页、批量上传页或结果可视化面板。

### 2.6 Ensemble ESM-2 wrapper forward 未实现

`scripts/ensemble_predict.py` 的 `_load_esm2_model()` 内部 wrapper 仍在 `forward()` 中直接 `raise NotImplementedError` [scripts/ensemble_predict.py:88](../scripts/ensemble_predict.py#L88)。这表示 ensemble voting/averaging 在选择 ESM-2 类型模型时不可用，且错误消息把“ESM2 model not available”作为运行时失败而不是 CLI 参数校验。

### 3.2 包安装元数据与 requirements 分裂

`requirements-core.txt` 明确声称是最小核心，不拉取 heavy/CUDA-sensitive 能力，并约束 `fastapi>=0.68.0`、`pydantic>=1.10,<3` [requirements-core.txt:1](../requirements-core.txt#L1) [requirements-core.txt:45](../requirements-core.txt#L45)。`requirements-analysis.txt` 对 `anndata`、`scvi-tools`、`zarr` 等有更精确联动约束 [requirements-analysis.txt:8](../requirements-analysis.txt#L8)。

但 `setup.py` 的 `install_requires` 仍把 `transformers>=4.30.0` 和 `lightning>=2.5.0` 放进核心安装 [setup.py:62](../setup.py#L62)，`extras_require["api"]` 又要求 `fastapi>=0.100.0`、`pydantic>=2.0.0` [setup.py:32](../setup.py#L32)，与本轮刚修复的 Pydantic/FastAPI 兼容目标冲突。`analysis`/`genki` extras 也落后于 `requirements-analysis.txt`，例如 `scvi-tools>=1.0.0` vs requirements 中的 `>=1.2.0` [setup.py:28](../setup.py#L28)。这是高严重度依赖债，会导致 `pip install -e .`、`pip install -r requirements-core.txt` 和 Docker 形成三套不同环境。

### 3.3 多 worker API 下限流和 metrics 不是全局一致

应用默认 Docker CMD 使用 `uvicorn ... --workers 4` [Dockerfile:87](../Dockerfile#L87)。但 `_RateLimitState` 是进程内字典，注释也说明它适合 single-worker 部署，multi-worker 需要外部 limiter [src/api/middleware.py:214](../src/api/middleware.py#L214)。`_RuntimeMetrics` 同样是进程内内存计数器 [src/api/middleware.py:69](../src/api/middleware.py#L69)。因此当前四 worker 镜像中每个 worker 有独立限流桶和独立 metrics，实际全局 RPM 可能约为配置值的 worker 倍数，`/metrics` 视请求落到哪个 worker 而变化。

### 3.4 脚本 CLI 完整性不一致

`scripts/data_statistics.py` 直接读取 `data/processed/train.csv`、`val.csv`、`test.csv`，输出固定到 `outputs/statistics`，没有 argparse 或输入/输出参数 [scripts/data_statistics.py:73](../scripts/data_statistics.py#L73) [scripts/data_statistics.py:79](../scripts/data_statistics.py#L79) [scripts/data_statistics.py:115](../scripts/data_statistics.py#L115)。这和主训练/推理脚本的可配置 CLI 风格不一致。

`scripts/integrate_data_v2.py` 仍有静默异常吞掉网络/API 单条重试失败 [scripts/integrate_data_v2.py:185](../scripts/integrate_data_v2.py#L185)，以及 JSON/解析异常静默忽略 [scripts/integrate_data_v2.py:554](../scripts/integrate_data_v2.py#L554)。对研究数据集构建来说，这会让丢数难以追踪。

### 3.5 大模块热点转移但未消失

拆分后旧报告中的 loader/API/app/external-tools 超大文件风险降低，但新的热点仍明显: `src/data/extended_pathway_kb.py` 792 行、`src/data/features.py` 789 行、`src/api/routes/predictions.py` 767 行、`scripts/predict.py` 733 行、`src/data/datasets.py` 727 行、`src/models/pretrained_encoders.py` 665 行、`src/models/architectures.py` 655 行。`src/api/routes/predictions.py` 同时承载 DAVF 输入收集、batch preprocessing、单样本预测、批量预测、variant 预测辅助逻辑 [src/api/routes/predictions.py:67](../src/api/routes/predictions.py#L67) [src/api/routes/predictions.py:128](../src/api/routes/predictions.py#L128) [src/api/routes/predictions.py:440](../src/api/routes/predictions.py#L440) [src/api/routes/predictions.py:594](../src/api/routes/predictions.py#L594)。

### 3.6 Mamba CPU fallback 仍是性能瓶颈

`SelectiveSSM` 支持 CUDA fused kernel 和 GPU parallel scan，但 CPU/fallback 仍进入 sequential Python loop [src/models/mamba_encoder.py:154](../src/models/mamba_encoder.py#L154) [src/models/mamba_encoder.py:174](../src/models/mamba_encoder.py#L174)。这不是 correctness bug，但对长序列 CPU smoke、无 `mamba_ssm` 环境和调试运行有性能风险。

## 5. 建议修复顺序

1. 先修 `setup.py` 与 requirements 分裂。这会直接影响新环境安装、CI、Docker 外部署和用户复现，是当前最可能造成“测试本机过、用户机器不过”的问题。
2. 同步 `docs/guides/quickstart.md` 与 `API_DOCUMENTATION.md`。README 已基本正确，复制当前权威流程即可快速降低误用成本。
3. 明确生产部署策略: 如果保持 4 worker，就把限流和 metrics 移到外部或 Redis；如果坚持进程内 limiter，则 Docker 默认 worker 改为 1。
4. 为 roadmap 建立 `deferred` 与 `cancelled` 的清晰边界。streaming/custom DB/GUI/API-key expansion 已取消，避免报告或文档继续把它们列为待实现能力。
5. 处理数据集成静默失败，并为 `scripts/data_statistics.py` 增加 CLI 参数。两项工作量小，但能提高真实数据流可审计性。

## 6. 本轮审计结论

项目主链路已经可运行，测试基线强，API 启动兼容性和 schema 兼容性已在提交 `8257ba4` 中修复。当前最主要风险不在模型主路径 correctness，而在“工程合约漂移”: packaging 元数据、文档、生产多 worker 行为、roadmap 状态描述与实际能力之间存在不一致。若下一轮优先清理这些合约层问题，项目会更接近可交付/可维护状态。
