- **报告日期**：2026-08-08
- **参考基线**：[`E2E训练与推理现状分析_2026-08-08.md`](E2E训练与推理现状分析_2026-08-08.md)

### 2.2 关键假设与边界

- **【假设】跨尺度训练的第一阶段输入为预计算 residue-level pLM embedding。** 这与现有 `MultiPLMEncoder` 的正常研究路径一致，同时避免每个 epoch 重复运行总计数 GB 的冻结 pLM。原始序列到 embedding 的正式批处理/缓存入口仍需单独实现。
- 版本化 `.npz` 只接受 `allow_pickle=False` 可加载数组，防止把任意 Python pickle 引入数据入口。
- 本轮“工程 E2E”使用小型、确定性数据验证代码闭环；真实图、真实扰动 target、真实 split 和真实效果门槛不在本地现有资产中，因此不宣称科学 E2E。

## 4. 三轮完整迭代记录

### 4.1 第一轮：本地 pLM 资产识别与 fail-fast

#### 问题识别

- 默认三路目录中已有完整权重，但另有两个目录只存在 `.part`；仅检查“目录存在”会产生假阳性。
- 原加载失败错误无法说明是 tokenizer 缺失、config 损坏、shard 缺失还是下载未完成。

#### 方案设计

- 用纯文件结构检查建立低成本门禁；只有通过门禁的绝对路径才能进入本地 `from_pretrained()`。
- 默认选择当前实际完整的三个目录，残片目录保留但不进入运行配置。

#### 代码修改

- `src/models/plm_assets.py`
- `scripts/validate_plm_assets.py`
- `src/models/cross_scale.py`
- `src/models/__init__.py`
- `configs/cross_scale/smoke.yaml`
- 新增 3 个单元用例和 2 个 CLI 集成用例。

覆盖：完整目录、残片目录、必需集合聚合报错，以及既有 MultiPLM shape/raw-sequence/loader 回归。

#### 本轮未解决

- 没有对数 GB 权重做完整 SHA-256 登记；结构完整不等于 release/内容已审计。
- 没有执行三路真实大模型联合前向；该验证需要独立 GPU/内存预算。

### 4.2 第二轮：版本化数据、训练、artifact 与精确续训

#### 问题识别

- 模型只能消费测试手工 batch；没有磁盘 schema、DataModule、训练 epoch 或发布 artifact。
- 初版 checkpoint 测试暴露 NumPy MT19937 `uint32` 状态在当前 Torch 序列化实现中不兼容。

#### 方案设计

- 用无 pickle 的 NPZ 固化预计算 embedding、图和 target 契约。
- 为跨尺度模型提供专用训练器；checkpoint 以自描述 schema 保存全部续训状态。
- 用 epoch 可寻址 sampler 消除“恢复后 shuffle 顺序漂移”。

#### 代码修改

- `src/data/cross_scale_dataset.py`
- `src/training/cross_scale_trainer.py`
- `scripts/train_cross_scale.py`
- `src/data/__init__.py`
- `src/training/__init__.py`
- 配置补充训练和标签字段；新增 3 个单元/集成用例。

#### 单元测试


回归证据：连续 2 epoch 与“1 epoch→保存→新进程语义恢复→第 2 epoch”最终每个 state-dict tensor 使用 `torch.equal()` 完全相等。

#### 本轮未解决

- 输入是预计算 embedding；原始序列→三路 embedding 的可恢复缓存/分片脚本尚未提供。
- split 之间只检查 shape 契约，尚未检查真实 `split_group` 重叠。

### 4.3 第三轮：artifact 加载与离线推理

#### 问题识别

- 只有 checkpoint 文件不足以可靠预测：config、标签、图维度或 embedding 维度漂移可能产生错误语义。
- 直接信任 manifest 中的 checkpoint 路径会带来路径穿越风险。

#### 方案设计

- artifact manifest 和 checkpoint 双向携带 config/labels，并在加载时交叉比较。
- 训练和推理复用相同 Dataset/collate；推理只接受安全 NPZ。
- 预测和 provenance 分文件导出。

#### 代码修改

- `src/inference/cross_scale_predictor.py`
- `src/inference/__init__.py`
- `scripts/predict_cross_scale.py`
- 数据合同增加 backbone 维度；训练入口强制标签词表；新增 4 个单元/集成用例。

#### 单元测试


覆盖 artifact round-trip、manifest/checkpoint config 漂移、路径穿越、数据异常和精确续训。

#### 集成测试

```text

```

实际执行：训练 CLI→artifact→新预测 CLI 进程→3 样本分两批推理→NPZ/provenance 校验。

#### 本轮未解决

- 未把跨尺度模型接入 FastAPI；当前支持的正式入口是离线 CLI。
- 未验证真实 GPU 吞吐、显存、OOM 恢复或三路真实 pLM 延迟。

## 6. 当前是否满足全部 E2E 技术要求

### 6.1 结论

**不满足“真实资产 + 科学效果 + 服务部署”的全部要求。**

当前准确状态为：

- 标准 PTM2CellNet：`engineering-smoke-ready`，继续具备生产候选工程链路；
- 跨尺度 PTM2CellNet：已从“组件/单 batch engineering smoke”提升到“预计算 embedding 的 train→val→test→artifact→reload→offline predict 工程 E2E”；
- 本地 pLM：默认三路目录通过结构完整性门禁，但没有完成统一 release/license/SHA-256 登记，也没有真实三路联合前向容量验收；
- 真实资产：仍不是 `real-asset-validated`；
- 科学结论：仍不是 `scientifically-accepted`。

该判定遵循参考文档第 3.3 节“不可宣称的能力”和第 6 节三层状态标签。[R-§3.3](E2E训练与推理现状分析_2026-08-08.md#33-当前不可宣称的能力) [R-§6](E2E训练与推理现状分析_2026-08-08.md#6-结论与建议)

### 6.2 仍未满足的主要原因

1. **真实监督和图资产缺失**：scPerturb/Norman/Adamson/Replogle、kinase-substrate、STRING/BioPlex/RegNetwork 等仍未形成可用本地 release 组合。
2. **缺少激活 profile**：`validate_data_manifest --strict` 只证明当前登记项合法，不证明跨尺度训练所需资产齐备。
3. **缺少 raw sequence→三路 embedding 的生产预计算入口**：模型能加载本地 pLM，训练合同能消费预计算 embedding，但中间的分片、缓存、resume、磁盘容量和 provenance 流程尚未固化。
4. **缺少真实防泄漏 split**：当前代码保证 split 文件合同兼容，不能证明蛋白同源组、donor、study 或 perturbation group 无交叉。
5. **缺少跨尺度 API 与容量门禁**：离线 CLI 已闭环，API schema、图缓存、并发、响应大小和多 worker 行为尚未实现。
6. **标准模型精确续训仍有债**：本轮精确续训只落在新跨尺度训练器；参考文档 P1-01 对标准 `scripts/train.py` 的判断仍成立。

## 9. 风险点与边界条件

### 9.1 可能失败的情况

- pLM 文件存在但内容位翻转：当前无登记 hash 时结构门禁无法发现。
- embedding 与 PTM residue 轴不一致：NPZ shape 一致仍不能自动证明生物 residue 对齐，必须由预计算 provenance 和抽样校验保证。
- 真实图节点数超过 `max_sensitivity_nodes`：当前 exact dense sensitivity 会 fail-fast，需要显式 sparse/iterative 实现，不能静默近似。
- 真实数据量过大：当前 `CrossScaleNPZDataset` 将单个 split 载入内存；需改为分片/mmap 或流式存储。
- 标签词表正确但 release 语义不同：artifact 只保证字符串和维度一致，仍需 release/profile 约束。
- 跨尺度 API 尚不存在，不能把离线 CLI 通过解释为在线服务通过。

### 9.2 需要确认或外部提供的内容

- 真实扰动数据、signal/cell graph 和 gene vocabulary 的 release、许可和路径；
- 三路 pLM 期望的最终型号是否继续采用当前完整默认组合，还是等待 `ankh3-large`/`esm2_t33_650M` 下载完成；
- 预注册科学指标、最低阈值、允许容差和外部验证集；
- 生产部署的 GPU 型号、内存/显存预算、吞吐和延迟 SLO。

## 10. 置信度

- **工程修复与自动化测试：高。** 有定向单元/集成、全量核心、独立 E2E、Ruff、mypy、compileall 和真实本地目录门禁的退出码证据。
- **真实资产可运行性：中低。** 默认 pLM 文件结构完整，但未完成统一 hash/release 审计和三路联合真实前向；图与真实监督仍缺。
- **科学有效性：低/未验证。** 没有真实训练、基线/消融、外部验证或预注册阈值证据，本报告不作效果声明。
