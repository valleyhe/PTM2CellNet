## 3. 每轮迭代执行情况与结果

### 3.1 第 1 轮：P1-01 标准 `--resume` 精确续训

**问题识别**
- 参考文档：标准模型 checkpoint「保存/恢复权重与 epoch，但 optimizer/scheduler 重新初始化」，不能视为精确续训。[R-§2.1 T-07](E2E训练与推理现状分析_2026-08-08.md) [R-§4.2 P1-01](E2E训练与推理现状分析_2026-08-08.md)
- 代码实证：`scripts/train.py` 从未把 `optimizer`/`scheduler` 挂载到 `ModelCheckpoint` 回调（`checkpoint_callback.optimizer` 恒为 None），因此保存的 checkpoint 实际不含优化器状态；resume 分支只恢复模型权重与 epoch/global_step，并输出「optimizer/scheduler 状态未保存」警告。
- 附带发现：`Trainer.fit()` 的 epoch 循环固定从 0 开始，即使 `trainer.epoch` 已恢复，续训仍会从头重训（`start_epoch` 缺失）。

**方案设计**
1. `ModelCheckpoint._build_checkpoint()` 增加 `scaler_state_dict` 与 `rng_state`（python/numpy/torch 三 RNG，语义对齐 `CrossScaleTrainer`），新增 `_capture_rng_state()`/`_restore_rng_state()`；
2. `scripts/train.py` 将 optimizer/scheduler 挂载到 checkpoint 回调，resume 分支按序恢复 optimizer → scheduler → scaler → RNG，并保留对旧版 checkpoint 的兼容（缺字段时显式警告不等价续训）；
3. `Trainer.fit()` 增加 `start_epoch` 参数（默认取 `self.epoch`），并让标准脚本恢复为 `checkpoint_epoch + 1`，避免重复训练已完成 epoch；
4. 训练状态（`checkpoint_best.pt`/`checkpoint_best_last.pt`）与推理 artifact（`best_model.pt` 裸 state_dict）分离，对齐 `train_lightning.py`/`train_pretrained.py` 既有契约。

**代码修改**
- `src/training/callbacks.py`：新增 RNG 捕获/恢复；`_build_checkpoint`/`_save_checkpoint`/`on_epoch_end` 支持 scaler 与 RNG。
- `src/training/trainers.py`：`fit(..., start_epoch=None)`。
- `scripts/train.py`：挂载 optimizer/scheduler；resume 恢复完整状态并从下一 epoch 开始；从最佳 checkpoint 导出裸 state_dict 到 `best_model.pt`；`--resume` 帮助文本更新。

**单元测试**
- 新增 `TestRngState`（捕获完整性、round-trip 等价、缺失键容错）、`TestModelCheckpointFullState`（optimizer/scheduler/scaler/rng 写入与 round-trip）、`TestExactResume`（start_epoch 语义、负值钳制、checkpoint 恢复）、`TestExactResumeEquivalence`（中断续训 vs 连续训练权重逐键一致、损失序列一致、optimizer 状态一致）。
- 结果：`tests/unit/training/test_callbacks.py` + `test_trainers.py` 共 79 passed。

**集成测试**
- `tests/integration/test_train_resume_cli.py` 5 用例：训练产物分离与最佳权重一致性、resume 从下一 epoch 继续、缺失 checkpoint fail-fast、旧版 checkpoint 兼容。
- 结果：5 passed（约 47s）。

**回归验证**
- `tests/unit/test_training_inference_consistency.py` + `tests/unit/training/`：223 passed。
- 标准 train/predict E2E 测试已包含在最终全量回归中；best_model.pt 回归测试覆盖最佳 checkpoint 权重一致性。
- 手动 E2E：`train.py`（smoke 配置）→ `predict.py`（单样本 + PTM 位点）输出完整概率分布，推理闭环通过。

### 3.2 第 2 轮：P1-04 manifest profile 激活机制

**问题识别**
- 参考文档：manifest 没有激活 profile/必需资产集合，`--strict` 可在关键研究资产全空时通过；「引入研究 profile 激活清单；profile 中声明为 required 的 release 缺失、哈希漂移或 schema 不合格时必须失败」。[R-§4.2 P1-04](E2E训练与推理现状分析_2026-08-08.md) [R-§5](E2E训练与推理现状分析_2026-08-08.md)
- 代码实证：`data/manifests/datasets.yaml` 全部 15 个数据源 `files[].required: false`；`validate_manifest()` 无 profile 概念；CLI 无 `--profile` 参数。

**方案设计**
1. manifest 顶层新增 `profiles` 声明：`standard_training`（必需 pmads）、`cross_scale_training`（必需 9 个监督/图数据集）、`cross_scale_inference`（必需图/词表资产）；
2. `validate_manifest(profile=...)`：profile 激活时其 `required_datasets` 中的 dataset 无论 per-file `required` 标志如何，路径为空、文件缺失（`--check-files`）、哈希缺失/漂移（`--verify-hashes`）均升级为硬错误；未知 profile 名、引用未知 dataset id、required/optional 重叠均显式报错；
3. `load_manifest`/CLI 透传 `profile`；报告输出 `profile` 与 `profile_required_datasets` 字段。

**代码修改**
- `src/data/data_manifest.py`：profile 解析与强制语义、引用一致性检查、报告字段。
- `scripts/validate_data_manifest.py`：新增 `--profile` 参数。
- `data/manifests/datasets.yaml`：新增 3 个 profile 声明（含中文注释说明门禁语义）。

**单元测试**
- 新增 `TestProfileActivation` 8 用例：required dataset 无路径必失败（无需 --check-files）、有路径+哈希通过、哈希漂移失败、未知 profile 失败、引用未知 dataset 失败、required/optional 重叠失败、项目 manifest 三个 profile 齐全、未指定 profile 时行为不变。
- 结果：`tests/unit/data/test_data_manifest.py` 24 passed。

**集成测试**
- 新增 4 个 CLI 用例（`tests/integration/test_data_manifest_cli.py`）：`--profile standard_training --check-files --verify-hashes` 通过；`--profile cross_scale_training` fail-fast（exit 2，报「required by profile」）；未知 profile 失败；不带 `--profile` 保持向后兼容通过。
- 结果：6 passed（28.0s）。

**回归验证**
- 原 `--check-files --strict`（无 profile）：ok=true、errors=[]、warnings=[]，与文档附录 A 基线一致。[R-附录A](E2E训练与推理现状分析_2026-08-08.md)

### 4.2 主要存在问题点及根本原因

1. **跨尺度真实资产验收（P0-01/P0-10 类）仍未闭环**。根本原因：scPerturb、Norman/Adamson、Replogle、scGeneScope、kinase-substrate、STRING、BioPlex、RegNetwork 等受控数据的许可与本地交付属于数据所有者职责；代码侧可判定的「资产齐备」门禁（profile）本轮已落地，`--profile cross_scale_training` 在当前资产状态下正确 fail-fast。[R-§4.1 P0-01](E2E训练与推理现状分析_2026-08-08.md)
2. **跨尺度模型仍未接入标准 API 服务链路**。根本原因：API 的初始化路由固定构建标准 `PTM2CellNet`；跨尺度 checkpoint 走独立 CLI 推理路径。当前变更已包含 `scripts/train_cross_scale.py`/`predict_cross_scale.py` 及其训练器和预测器，但 API 模型类型路由尚未实现。[R-§4.1 P0-02](E2E训练与推理现状分析_2026-08-08.md)
3. **多实例速率限制与完全锁定环境（P2/P1-06）未处理**。根本原因：进程内限流状态在多 worker 间不共享；requirements 分层但无 lock 文件或容器 digest。属运维收口范畴。[R-§4.2 P1-06](E2E训练与推理现状分析_2026-08-08.md) [R-§4.3](E2E训练与推理现状分析_2026-08-08.md)
4. **`data/validation.py`、`api/routes/initialize.py`、`training/self_supervised.py` 覆盖率仍低**。本轮聚焦了 callbacks/data_manifest，其余低覆盖模块（含异常与状态转换分支）待阶段 E 逐模块推进。[R-§2.3](E2E训练与推理现状分析_2026-08-08.md)

## 5. 未解决问题及后续策略

1. **真实资产科学验收（P0-10）**：不可用 8 个真实资产测试的 skip 推出验收通过；需在受控 nightly runner 上以真实 release 跑 train→val→test，并做 PMADS Ridge / 标准模型 / 跨尺度同 split 对比。[R-§3.3](E2E训练与推理现状分析_2026-08-08.md) [R-§5 阶段D](E2E训练与推理现状分析_2026-08-08.md)
2. **跨尺度 raw sequence→预计算 embedding 生产入口**：模型能消费预计算 embedding，但分片/缓存/resume/磁盘容量/provenance 流程未固化（并行工作已提供数据契约与训练器，仍缺生产预计算器）。
3. **文档一致性自动检查**：数据规模、测试计数、覆盖率基线与「最新报告」链接需由 CI 或更新脚本校验，避免过期权威。[R-§4.3](E2E训练与推理现状分析_2026-08-08.md)
4. **`estimate_max_batch_size` 硬编码层数与长序列窗口逻辑**：需先从实际模型配置派生层数、建立可重复 benchmark 再优化。[R-§4.3](E2E训练与推理现状分析_2026-08-08.md)
